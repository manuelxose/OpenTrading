# Domain Glossary (OpenTrading)

Compact bootstrap of canonical vocabulary from `docs/architecture.md`. Use these terms
exactly; do not invent synonyms (e.g. it is always `OrderIntent`, never "MT4 order").

## Core objects (§15)

`Instrument`, `MarketSnapshot`, `ResearchPacket`, `QuantSignal`, `LLMSignal`,
`FusedSignal`, `TradeProposal`, `RiskDecision`, `OrderIntent`, `ExecutionReport`,
`PositionSnapshot`, `TradeOutcome`, `PostTradeReview`, `MemoryEpisode`,
`FactorCandidate`, `ModelCandidate`, `StrategyCandidate`, `ExperimentRun`,
`PromotionDecision`.

## Operating modes (§6)

`RESEARCH` → `BACKTEST` → `PAPER` → `LIVE_GATED` → `LIVE_AUTO`.
No LLM may change the mode. LIVE requires promotion lifecycle (§18):
IDEA → CANDIDATE → BACKTESTED → WALK_FORWARD_OK → ROBUSTNESS_OK → PAPER → SHADOW →
LIVE_GATED → LIVE_AUTO → RETIRED.

## Order state machine (§9)

CANDIDATE → RISK_REJECTED → APPROVED → ORDER_INTENT → SUBMITTED → ACKNOWLEDGED →
PARTIALLY_FILLED → FILLED → CANCELLED → REJECTED → RECONCILED → CLOSED → REVIEWED.

## Risk language (§7)

`RiskDecision` is `APPROVE {approved_quantity, approved_stop, risk_amount, policy_version}`
or `REJECT {reason_codes[]}`. Never a bare `{"approved": true}`.

## Kill switches (§10)

Strategy kill, instrument kill, portfolio kill (`NO_NEW_POSITIONS`), emergency kill
(`CANCEL_PENDING` + `NO_NEW_POSITIONS` + optionally flatten), dead-man switch
(heartbeat loss → new trades BLOCKED; broker SL/TP remain).

## Data (§13)

- Postgres+Timescale = transactional truth (accounts, strategies, signals, proposals,
  risk decisions, order intents, executions, positions, trades, snapshots, audit).
- Parquet+MinIO = heavy history (`/raw`, `/bronze`, `/silver`, `/gold`).
- Redis = cache, locks, ephemeral, **Redis Streams event bus**.
- FalkorDB+Graphiti = temporal semantic memory (ontology §11).

## Memory (§11)

Graphiti entities: Instrument, Company, Sector, Currency, MacroEvent, NewsEvent, Thesis,
Signal, MarketRegime, Strategy, Factor, Model, Experiment, Trade, Position, RiskEvent,
DataSource. Relations: SUPPORTS, CONTRADICTS, INVALIDATES, GENERATED_BY, CAUSED_BY,
CORRELATES_WITH, ACTIVE_IN_REGIME, FAILED_IN_REGIME, EXECUTED_AS, RESULTED_IN,
LEARNED_FROM. Short/medium/long-term layers inspired by FinMem (concepts only).
Every query in simulated context takes `as_of` (§12).

## Events (§14)

`market.snapshot.created`, `research.*`, `quant.signal.created`, `llm.signal.created`,
`signal.fused`, `risk.approved/rejected`, `order.intent.created` … `order.rejected`,
`position.updated`, `trade.closed`, `postmortem.completed`, `memory.episode.created`,
`strategy.candidate.created/promoted/retired`, `system.safe_mode.entered/exited`.
Envelope fields: schema_version, event_id, trace_id, event_time, ingested_at, producer,
payload, provenance.

## Trust zones (§29)

Zone 1 internet/LLM/market-data · Zone 2 Core Quant Platform · Zone 3 broker/MT4.
LLMs never see broker credentials, MT4 credentials, execution sockets, or secret-store.

## Tooling split (§24)

- **Graphify** = codebase knowledge graph for development context (`graphify-out/`).
- **Graphiti** = temporal trading memory (runtime).
- **Langfuse** = LLM observability; **Prometheus/Grafana** = ops observability.
- **Obsidian** = human knowledge UI (`vault-trading/`, autogenerated marked as such).
